1 רקע ומטרה

האתר new-unlock (UNLOCK — גבי המנעולן) מתארח ב-Netlify עם deploy אוטומטי מ-GitHub, אבל כל ה-backend רץ על Firebase: Firestore (מסד נתונים), 12 Cloud Functions, ו-Firebase Auth (Google Sign-In לפאנל הניהול).

זה יוצר שני צינורות deploy נפרדים — Netlify לפרונט, ו-firebase deploy ידני לבאקנד — עם ניהול secrets כפול (Netlify env vars מול Firebase Secret Manager), וגם שלוש מימושים שונים ונפרדים של בדיקת "האם זה המנהל" בשלושה מקומות שונים בקוד.

המטרה: לאחד הכל לפייפליין אחד (Netlify), עם Turso (מסד SQL מבוזר, מבוסס libSQL) כמסד הנתונים, ואימות קוד-במייל חד-משתמש (רק gal9amar@gmail.com יכול להתחבר) במקום Google Sign-In.

אילוץ קריטי: האתר החי תלוי ב-Firebase בכל בקשה כרגע — המעבר חייב לקרות בהדרגה, בלי downtime.

עזרים משותפים בקוד הקיים

verifyAdmin() — בודק Firebase ID token מול secret ADMIN_EMAIL.

cors() — בודק Origin מול ALLOWED_ORIGINS.

sendMail() — nodemailer + Gmail SMTP עם secret GMAIL_APP_PASSWORD.

תלויות Firebase נוספות (מעבר לפונקציות)

scripts/generate-ssg.js — סקריפט CI (.github/workflows/ssg.yml) שמשתמש ב-firebase-admin + service-account JSON כדי לקרוא את products ולבנות סטטית את products/{slug}/index.html + sitemap.xml.

netlify/functions/update-reviews.js — מימוש שלישי ונפרד של בדיקת admin: קורא ישירות ל-Identity Toolkit REST API (FIREBASE_API_KEY + ADMIN_EMAIL כ-Netlify env vars).

pages/admin.html — Firebase JS SDK מלא, signInWithPopup מול Google, getIdToken() נשלח כ-Bearer בכל קריאת admin.

קונפיג לסגירה בסוף: firebase.json, .firebaserc, firestore.rules, functions/.env, תלויות Firebase ב-functions/package.json וב-package.json השורש, FIREBASE_SERVICE_ACCOUNT ב-GitHub Actions, FIREBASE_API_KEY/ADMIN_EMAIL הישנים ב-Netlify.

5 אימות קוד-במייל (מחליף Google Sign-In)

יש משתמש מורשה יחיד — gal9amar@gmail.com — ולכן אין צורך בזרימת OAuth מלאה.

1. request-code

POST · ציבורי
  • אין קלט כתובת מייל — הכתובת המורשית קבועה בצד השרת בלבד
  • Rate-limit (לדוגמה: מקסימום 3 קודים ב-10 דקות), נבדק מול טבלת auth_codes
  • יוצר קוד בן 6 ספרות, שומר hash + תוקף (10 דק') בטבלה
  • שולח במייל דרך אותו sendMail (Gmail SMTP)

2. verify-code

POST · ציבורי
  • מקבל קוד, בודק מול הרשומה האחרונה שלא פגה ולא שומשה
  • אם תואם → מנפיק JWT חתום (secret AUTH_JWT_SECRET, תוקף 7 ימים)
  • מסמן את הקוד כ-used

3. מודול verify-admin משותף

netlify/functions/_lib/
  • מוודא חתימת JWT + תוקף (stateless, בלי DB lookup)
  • כל הפונקציות המוגנות ישתמשו באותו מודול — מאחד את שלושת המימושים הקיימים היום למקום אחד

4. admin.html

Frontend
  • מחליף מסך Google Sign-In בכפתור "שלח קוד אימות" → שדה 6 ספרות → "אמת"
  • שומר JWT ב-localStorage, שולח כ-Authorization: Bearer <jwt> בכל קריאה

7 מה נדרש ממך כדי להתחיל

  1. חשבון Turso — אם אין, יצירה ב-turso.tech (חינמי בהיקף הזה), ואז מסירת TURSO_DATABASE_URL + TURSO_AUTH_TOKEN.
  2. גישה ל-Netlify env vars — בניגוד ל-Firebase (שם היה חיבור CLI ישיר), אין דרך אוטומטית להגדיר משתני סביבה ב-Netlify — תצטרך להוסיף בעצמך לפי הוראות מדויקות, או לספק Netlify auth token אם תרצה שזה ייעשה ישירות.
  3. אישור רצף השלבים — לא לדלג ישר ל"סגירת Firebase" לפני שהחלופה מאומתת במלואה.
